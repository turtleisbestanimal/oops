# 이메일 수집 설치 안내

랜딩페이지의 이메일 입력칸 → Google 스프레드시트로 한 줄씩 쌓이게 만드는 절차입니다.
한 번만 하면 됩니다. **10분쯤 걸립니다.**

## 왜 이런 구조인가

지금 사이트는 정적 사이트라 "받아 적어 둘 서버"가 없습니다.
그 역할을 구글이 대신 해 줍니다.

```
방문자 브라우저                Google 서버                내가 보는 곳
 이메일 입력
   └ collect.js ──POST──▶ Apps Script 웹앱 ──▶ 스프레드시트 한 줄 추가
```

Apps Script 웹앱 주소는 **공개되어도 안전합니다.** `doPost`만 열려 있어서
쓰기만 가능하고, 이미 쌓인 이메일을 읽어 갈 수는 없습니다.

---

## 0. 먼저 — 반드시 개인 Gmail 계정으로

학교·회사 Google Workspace 계정(`@handong.ac.kr` 등)은 조직 정책으로
Apps Script 웹앱의 외부 공개를 막아두는 경우가 많습니다. 그러면 3단계에서
`모든 사용자` 선택지가 아예 없고, 배포해도 방문자에게 **403 액세스 거부**가
납니다. 시작 전에 브라우저 오른쪽 위에서 **개인 Gmail 계정으로 전환**하세요.

## 1. 스프레드시트 만들기

1. <https://sheets.new> 접속 → 새 스프레드시트 생성
2. 이름을 알아보기 쉽게 변경 (예: `oops 사전 신청`)

시트 탭이나 헤더 행은 만들지 않아도 됩니다. 첫 제출 때 스크립트가
`emails` 시트와 헤더를 자동으로 만듭니다.

## 2. Apps Script 붙이기

1. 그 스프레드시트에서 **확장 프로그램 → Apps Script**
2. 편집기에 있던 `function myFunction() {}` 를 **전부 지우고**,
   이 폴더의 [`Code.gs`](./Code.gs) 내용을 **그대로 붙여넣기**
3. 저장 (⌘S)

> 시트에서 열어 만들었으므로 `SHEET_ID`는 **비워 둔 채로** 두세요.
> 스크립트가 그 시트를 자동으로 찾아갑니다.

## 3. 웹앱으로 배포

1. 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴(유형 선택) → **웹 앱**
3. 설정:
   - **다음 사용자로 실행**: `나`
   - **액세스 권한이 있는 사용자**: **`모든 사용자`** ← 여기가 제일 중요합니다
4. **배포** → 권한 승인 (본인 구글 계정 선택)
   - "이 앱은 확인되지 않았습니다" 경고가 뜨면
     **고급 → (프로젝트 이름)(으)로 이동** 을 눌러 진행하세요.
     내가 만든 스크립트라 정상입니다.
5. 배포 후 나오는 **웹 앱 URL**을 복사

```
https://script.google.com/macros/s/AKfycb....../exec
```

> **액세스 권한을 `나`로 두면 실패합니다.** 방문자는 내 구글 계정으로
> 로그인해 있지 않기 때문입니다. 반드시 `모든 사용자`여야 합니다.

## 4. 사이트에 주소 넣기

저장소 루트의 [`collect.js`](../collect.js) 맨 위 `CONFIG.endpoint` 에 붙여 넣습니다.

```js
var CONFIG = {
  endpoint: 'https://script.google.com/macros/s/AKfycb....../exec',
  ...
```

커밋하고 push하면 Vercel이 자동 재배포합니다.

## 5. 확인

1. 배포된 사이트에서 이메일을 입력하고 화살표 클릭
2. 입력칸 아래에 **"등록됐습니다. 오픈하면 알려 드릴게요."**
3. 스프레드시트에 줄이 생겼는지 확인

기록되는 열: `email` · `submitted_at` · `source`(hero/cta) · `referrer` · `user_agent`

## 문제가 생기면

브라우저에서 **F12 → Console** 을 먼저 보세요. `[collect]` 로 시작하는
메시지에 원인이 찍힙니다.

| 증상 | 원인 | 해결 |
|---|---|---|
| "수집 주소가 아직 설정되지 않았습니다" | `CONFIG.endpoint`가 비어 있음 | 4단계 |
| 콘솔에 CORS 오류 | 배포 시 액세스 권한이 `모든 사용자`가 아님 | 3단계를 다시 |
| "전송에 실패했습니다"만 반복 | 웹앱 URL이 `/exec`가 아니라 `/dev`로 끝남 | `/exec` 주소를 쓰세요 |
| 주소를 열면 **403 액세스 거부** | 액세스 권한이 `나` 또는 조직 내부로 제한됨 | 배포 관리 → 수정 → `모든 사용자`. 드롭다운에 그 항목이 없으면 Workspace 정책이 막은 것이므로 개인 Gmail로 다시 |

배포가 제대로 됐는지 확인하는 가장 빠른 방법: **시크릿 창에서 웹앱 URL을 열어보세요.**
`{"ok":true,"service":"oops-email-collect"}` 가 보이면 성공입니다.
로그인 화면이나 "액세스 권한 필요"가 뜨면 아직 공개되지 않은 것입니다.
| 시트에 아무것도 안 쌓임 | Apps Script 실행 로그 확인 | 편집기 → 실행 기록 |

## 코드를 고칠 때 주의

Apps Script는 **코드를 저장해도 배포에는 반영되지 않습니다.**
`배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포`를 눌러야
바뀐 코드가 적용됩니다. 이때 **URL은 그대로 유지**됩니다.

## 디자인을 다시 export한 뒤

`index.html`이 통째로 덮어써지므로, `</body>` 바로 앞에 이 한 줄을
다시 넣어야 합니다.

```html
<script src="./collect.js" defer></script>
```

`collect.js`와 이 폴더는 export의 영향을 받지 않으니 그대로 두면 됩니다.

## 개인정보 관련

이메일은 한국 개인정보보호법상 개인정보입니다. `collect.js`는 입력칸 아래에
수집 동의 체크박스와 고지 문구를 자동으로 붙입니다.

- 고지 문구를 바꾸려면 `CONFIG.consentLabel` / `CONFIG.consentNote`
- 체크박스를 빼려면 `CONFIG.requireConsent`를 `false` (권장하지 않습니다)

실제로 메일을 발송할 때는 수신거부 방법을 함께 안내해야 하고,
광고성 정보라면 제목에 `(광고)` 표기가 필요합니다.
